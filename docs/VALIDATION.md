### Atualização 0.5.3 — aplicação real no WhatsApp Web

- Reproduzida a falha da 0.5.2 com o Chrome realmente ativo e o campo gravável. Esperar o `AXValue` não bastou: o setter de `AXSelectedText` não alterou o rascunho. A primeira hipótese de simples atraso do renderer foi insuficiente.
- Evidência de protocolo: o [setter Cocoa do Chromium](https://github.com/chromium/chromium/blob/main/ui/accessibility/platform/ax_platform_node_cocoa.mm) envia `kReplaceSelectedText`, mas o [despachante de acessibilidade do renderer web](https://github.com/chromium/chromium/blob/main/content/renderer/accessibility/render_accessibility_impl.cc) agrupa essa ação em `NOTREACHED()`. Isso fundamenta um adaptador específico, sem inferir que todas as versões/campos se comportem igualmente.
- O adaptador da aplicação usa as APIs públicas [entrada Unicode](https://developer.apple.com/documentation/coregraphics/cgevent/keyboardsetunicodestring(stringlength:unicodestring:)) e `CGEvent.postToPid`, apenas depois de Aplicar, com destino ativo, identidade/texto/seleção exatos. A área de transferência não é usada para propostas curtas. Não há repetição automática depois de envio. Diagnóstico em stderr registra fase e adaptador, sem texto.
- **Aplicação de palavra confirmada na interface real:** rascunho artificial `hi my frien how are he ?` → `hi my frien how are they?`. O log registrou `phase=selection-confirmed bundle=com.google.Chrome` e `phase=verified adapter=chrome-text-input`. Um Cmd+Z restaurou exatamente o rascunho. A aplicação não valida a escolha semântica do modelo de trocar `he` por `they`; registra apenas o que o cartão ofereceu e o editor recebeu.
- **Aplicação de frase confirmada na interface real:** Reformular frase ofereceu `hey mate, what's up with him?`; Aplicar sugestão produziu exatamente esse texto no campo, confirmado pelo mesmo adaptador. O primeiro caminho de entrada em blocos exigiu dois Cmd+Z; ambos foram executados e o rascunho original foi restaurado.
- Ajuste subsequente para frases maiores: uma única colagem nativa após validação; preserva todos os formatos disponíveis da área de transferência e restaura condicionalmente pelo `changeCount`, sem sobrescrever uma cópia nova. Não tenta colar se não puder capturar todos os formatos existentes. ### Atualização 0.4.2 — cartão exibindo apenas uma letra

## Limitações conhecidas

- O SDK Command Line Tools não contém os plugins de macros SwiftUI/FoundationModels usados em alguns exemplos nem XCTest. Esta implementação evita essas macros e usa um executável de verificações sem dependências externas.
- O mecanismo de build padrão do Swift 6.4 encontrou restrição ao gerar símbolos. O script usa o mecanismo nativo do SwiftPM e desativa símbolos de debug para a distribuição local. Esse mecanismo está marcado como deprecated pelo toolchain; migrar/validar o build com Xcode completo antes de distribuir.
- A assinatura ad hoc pode fazer o macOS exigir nova autorização de Acessibilidade após uma recompilação. A permissão do processo de desenvolvimento não prova autorização permanente do app aberto isoladamente pelo Finder.
- Não houve teste com a rede desligada nem avaliação ampla de gramática. O código usa explicitamente `SystemLanguageModel`, sem provedor remoto ou ferramentas de rede.
- Um corretor Grammarly já instalado pode adicionar sua própria interface no Chrome. Não atribuir marcas de outra extensão a este aplicativo.
- Compatibilidade universal, texto rico, idiomas mistos dentro de uma frase e agrupamento semântico de correções dependentes ainda precisam de trabalho e avaliação específica.

Os arquivos de teste são artificiais. Documentos pessoais do usuário não foram editados como parte da validação.
